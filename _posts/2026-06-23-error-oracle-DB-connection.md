# 리눅스 서버 배포 후 잘못된 Oracle DB 연결 설정 해결

## 문제 상황

ITSM 시스템 기능 수정 후 리눅스 서버에 배포를 진행하였으나 정상적으로 동작하지 않았습니다.

초기에는 SQL 오류로 판단하였지만 로그를 확인하는 과정에서 데이터베이스 연결 정보가 예상과 다르게 설정되어 있는 것을 발견하였습니다.

---

## 원인 분석

서버 내 환경설정 파일을 확인하던 중 기존 설정 파일이 그대로 남아 있었고, 애플리케이션이 의도한 데이터베이스가 아닌 다른 Oracle 서버로 접속하고 있었습니다.

예를 들어 실제 접속해야 하는 정보는 다음과 같았습니다.

```properties
jdbc.url=jdbc:oracle:thin:@10.0.0.10:1521:ORCL
jdbc.username=itsm
```

그러나 서버 설정에는 이전 환경 정보가 남아 있었습니다.

```properties
jdbc.url=jdbc:oracle:thin:@192.168.xxx.xxx:1521:ORCL
jdbc.username=test
```

이로 인해 테이블 구조 및 데이터가 일치하지 않아 Oracle 관련 오류가 발생하였습니다.

---

## 해결 과정

1. 서버 환경설정 파일 확인
2. 백업 파일 및 기존 설정 파일 검토
3. Oracle 접속 정보 확인
4. 올바른 DB 서버 정보로 수정
5. 애플리케이션 재기동 후 테스트 수행

---

## 결과

환경설정을 수정한 후 정상적으로 데이터가 조회되었으며 Oracle 오류가 해결되었습니다.

또한 배포 시 환경설정 파일과 데이터베이스 연결 정보를 반드시 확인해야 한다는 점을 경험할 수 있었습니다.

---

## 배운 점

처음에는 SQL 또는 프로그램 로직의 문제라고 생각하였으나, 

서버 로그를 분석하는 과정에서 잘못된 DB 연결 설정이 원인임을 확인할 수 있었습니다. 

이 경험을 통해 장애 대응 시 가장 먼저 확인해야 할 것은 로그이며, 

정확한 로그 분석이 문제 해결 시간을 크게 단축시킨다는 점을 배울 수 있었습니다
